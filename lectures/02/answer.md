## 宿題

- 取り組んだレベル：実装

- 変えた設定やデータ：
営業時間：11:30〜21:00（ラストオーダー20:30）、毎週水曜日が定休日
予約方法：電話または公式ウェブサイトで受け付け、利用日の30日前から予約可能。

アレルギー対応：利用日の3日前までに連絡が必要。ただし、調理環境での完全な混入防止は保証できない
GROUNDEDは、上記5項目について質問を作成し、FAQに記載された情報を根拠として回答するようにした。UNGROUNDEDは、FAQに記載されていない機能やサービスに関する質問を用意した。例えば、個室の利用、駐車場、子ども用の椅子、ペット同伴、テイクアウトなどである。これらはFAQだけでは回答できない質問として扱い、needs_review を true とした。

- 結果（比較表や数字）：
学習前は、format_rate = 61.90% / content_rate = 4.76% だった。学習後は、format_rate = 100% / content_rate = 85.71% となり、回答形式と回答内容の両方に改善が見られた。
学習後に残った不正解は3問だった。「ラストオーダーは何時ですか」という根拠がある質問に対して、支払い方法を回答してしまった。「席の利用時間に制限はありますか」という根拠がない質問に対して、営業時間を回答してしまった。「予約時に座席の場所を指定できますか」という根拠がない質問に対して、予約方法や予約可能期間を回答してしまった。
また、知識を問う質問では、学習前はJSON形式を守れない回答や根拠のない断定が見られた。学習後は、FAQに根拠がある営業時間の質問に正しく回答し、FAQに記載されていない質問に対しては確認を求めるようになった。

- ファインチューニングが向く場面・向かない場面についての考察：
今回の実験結果から、ファインチューニングは、決められた情報に基づいて回答する方法や、根拠がない場合には確認を求めるといった回答ルールを学習させる用途に効果があると考えられる。
一方で、通常のtestでは、質問と異なるFAQの情報を回答したり、根拠がない質問に対して関連する情報を使って断定したりするケースが残った。そのため、回答形式や基本的な判断ルールを学習できても、あらゆる質問に対して適切な情報を取り出せるようになるとは限らない。
また、営業時間や料金など、頻繁に変更される情報をモデル自体に学習させると、情報が変更されるたびに再学習が必要になる可能性がある。そのため、最新情報を扱う場合には、外部のデータベースやRAGなどを利用して必要な情報を取得する仕組みが適していると考える。
以上から、ファインチューニングは、回答形式や業務上のルール、特定の分野における回答方法を統一する場面に向いている。一方、頻繁に更新される情報の管理や、未知の質問に対して常に正確な情報を回答することには限界があり、外部の情報検索機能などと組み合わせることが重要だと考えた。
